## 1.1. Overview of the MTUOC Project

The [MTUOC project](https://mtuoc.github.io/), developed at the Arts and Humanities Department of the Universitat Oberta de Catalunya (UOC), is a comprehensive open-source initiative designed to facilitate the training, customization, use, and integration of neural machine translation (NMT) and statistical machine translation (SMT) systems, as well as Large Language Models (LLMs) for translation, within professional translation environments.

While most modern MT toolkits are distributed under free and open licenses, their practical adoption in real-world professional workflows presents several challenges:

* **Technical Skills Barrier:** Toolkits often require medium-to-high programming knowledge (Python, Bash scripting) and may lack comprehensive, user-friendly documentation.
* **Integration and Interoperability:** Custom-trained engines cannot always be easily or natively integrated into popular Computer-Assisted Translation (CAT) tools used by professional translators.
* **Hardware Requirements:** While training new NMT models requires powerful dedicated GPUs and significant RAM, running inference — translating text with an already trained model — requires considerably fewer computational resources.

MTUOC addresses these issues by providing well-documented scripts, accessible graphical user interfaces, and a highly configurable local server. All project components are distributed under a free GNU GPL license, allowing individual professionals, language service providers (LSPs), and educational organizations to maintain technological independence and data confidentiality.

---

## 1.2. Key Ecosystem Components

The project provides a comprehensive ecosystem of modular tools covering different stages of the machine translation lifecycle:

* **Corpus Creation:** Utilities designed to extract and convert proprietary translation formats (such as TMX, SDLTM, and XLIFF) into plain tabular text files. The project includes automated programs for sentence-level document alignment using *Hunalign*, as well as tools for comparable corpus mining using sentence embeddings with *SBERT*.
* **Corpus Cleaning and Combination:** Advanced scripts to remove HTML/XML formatting tags, normalize special characters, filter out corrupt segments by length ratios, and verify language identification using *fasttext*. An algorithm to clean and rescore large parallel corpora is also available. Additionally, the project includes utilities to expand specialized domain corpora by retrieving similar segments from large general corpora based on language model perplexity.
* **Preprocessing and Training:** Standardized data preparation tools, including tokenizers, truecasers, and subword segmentation models such as BPE and *SentencePiece*. The project provides pre-configured training scripts and configuration files for engines such as *Moses*, *Marian*, *OpenNMT*, and *Eole*, as well as step-by-step guides and scripts to fine-tune open LLMs specifically for translation tasks.
* **Free Pre-trained Engines:** The project packages and distributes pre-trained, ready-to-use NMT models for several language pairs and specialized domains.
* **Client Programs:** Dedicated desktop applications and a web interface for translating standalone documents are distributed with the suite. A specialized post-editing environment is also under active development.

## 1.3. The MTUOC-Server

**MTUOC-server** is a central component of the architecture, designed specifically to address the interoperability gap between backend machine translation engines and frontend professional CAT tools.

### 1.3.1. Architecture and Workflow

The server operates on a lightweight client-server model, acting as a middleware bridge. The translation workflow follows a clear multi-step process:

1. **Request:** The client application (e.g., a CAT tool plugin or translation desktop application) sends a source segment to MTUOC-server.
2. **Preprocessing:** The server preprocesses the incoming segment by applying the required pipeline (tokenization, truecasing, subword segmentation with SentencePiece, etc.).
3. **Inference:** The server forwards the processed segment to the underlying MT engine or local/remote LLM.
4. **Postprocessing:** After receiving the translated output from the engine, the server applies the corresponding inverse processing steps (detokenization, undoing subword splits, character re-normalization, etc.).
5. **Response:** The final clean translated segment is formatted and returned to the client.

### 1.3.2. Protocol Interoperability

One of the key features of MTUOC-server is its ability to communicate using multiple protocols, including MTUOC, Moses, ModernMT, OpenNMT, and NMTWizard. The server can emulate these protocols, and new protocols can be added in the future.

For instance, you can use a fast Marian neural engine while configuring MTUOC-server to behave like a Moses server. This makes it possible to integrate different translation engines with CAT tools and other client applications without requiring them to support each underlying engine directly.

### 1.3.3. Supported Systems and LLMs

The server supports a broad range of translation technologies:

* **NMT Systems:** Open-source engines and models such as Marian, OpenNMT, Moses, OpusMT, NLLB, CTranslate2, and Apertium, as well as commercial APIs such as DeepL and Google Translate.
* **Large Language Models (LLMs):** The server integrates models such as Salamandra, Bloom, ChatGPT, DeepSeek, and Tower. Users can access these models via API or by downloading models from Hugging Face and running them locally using the `transformers` library. The server also allows users to define custom translation prompts and use regular expressions to extract the translated text from the LLM response.

### 1.3.4. Features for Professional Workflows

To support professional translation workflows, MTUOC-server includes several advanced features:

* **XML/HTML Tag Restoration:** Neural engines may struggle to place formatting tags correctly, for example when processing DOCX files. The server uses an algorithm based on word or subword alignments from the MT system to restore tags. If the MT system does not provide alignments, external `fast_align` models can be used.
* **Translation Memories:** The server can integrate translation memories and return a translation memory match when its similarity score exceeds a predefined threshold.
* **CAT Tool Plugins:** Dedicated plugins are available for direct integration with OmegaT and RWS Trados Studio.

### 1.3.5. Hardware and Platform Compatibility

MTUOC-server is multiplatform and runs on Linux, Windows, and macOS. While training MT systems requires powerful hardware, running MTUOC-server for translation does not necessarily require a GPU. It can run on standard consumer computers, making NMT and LLM technology more accessible while allowing translators to keep client data on their local machines.

## 1.4. Starting and Stopping an MTUOC-Server

### 1.4.1. Getting MTUOC-Server, Versions and Prerequisites

To get MTUOC-server, go to the [MTUOC-server GitHub repository](https://github.com/mtuoc/MTUOC-server).

If you have a Python 3 interpreter installed on your system, you can use the Python source code and install the required dependencies listed in [`requirements.txt`](https://github.com/mtuoc/MTUOC-server/blob/main/requirements.txt).

Alternatively, you can go to the [Releases](https://github.com/mtuoc/MTUOC-server/releases) section and download the binary version for your operating system.

### 1.4.2. Running MTUOC-Server from the Terminal

To start MTUOC-server using the default `config-server.yaml` configuration file, enter the following command in the terminal:

```bash
python3 MTUOC-server.py
```

If you want to use a specific configuration file, for example `config-server-opusmt-eng-spa.yaml`, use:

```bash
python3 MTUOC-server.py config-server-opusmt-eng-spa.yaml
```

To stop MTUOC-server, enter:

```bash
python3 MTUOC-stop-server.py
```

or, when using a specific configuration:

```bash
python3 MTUOC-stop-server.py config-server-opusmt-eng-spa.yaml
```

A complete engine can be downloaded and configured using **MTUOC recipes**. Available recipes can be found in the [MTUOC-recipes repository](https://huggingface.co/datasets/aoliverg/MTUOC-recipes/tree/main).

You can download a recipe in two ways.

If you already have the recipe as a file:

```bash
python3 MTUOC-downloader.py recipeAina-cat-eng.yaml
```

Alternatively, you can provide the direct link to the recipe:

```bash
python3 MTUOC-downloader.py https://huggingface.co/datasets/aoliverg/MTUOC-recipes/resolve/main/recipeAina-cat-eng.yaml
```

### 1.4.3. Using the MTUOC-Server Manager

A graphical user interface (GUI), **MTUOC-server-manager.py**, is provided to simplify the process of starting, stopping, testing, and configuring MTUOC servers.

When you start the application, the following interface is displayed:

<img width="675" height="450" alt="MTUOC-server Manager interface" src="https://github.com/user-attachments/assets/c4c3ad0e-7007-451b-8ff8-0e2395778aa1" />

The application is organized into five tabs:

* **Control:** Select an engine through its configuration file, start and stop the server, and check its status.
* **Test:** Send sentences to the active server for translation.
* **Configuration Editor:** Edit the basic configuration of the translation engine.
* **Aux. Editor:** Edit additional configuration files required by some models.
* **Recipes:** Download complete pre-configured engines from MTUOC recipes.

#### The Control Tab

<img width="675" height="450" alt="MTUOC-server Manager Control tab" src="https://github.com/user-attachments/assets/aeb6edf7-8765-4799-9ff0-90cbd8a4bcfb" />

In this tab, you can select one of the available server configuration files. These files should be placed in the same directory as MTUOC-server-manager. Once you have selected a configuration, click **Start** to launch the server.

The console displays relevant information about the running server. Use the **Stop** button when you want to stop it.

#### The Test Tab

<img width="675" height="450" alt="MTUOC-server Manager Test tab" src="https://github.com/user-attachments/assets/c873c944-4a9d-460e-8716-ea610b02ea73" />

In the **Test** tab, you can write or paste sentences or paragraphs and send them to the active translation system. This provides a simple way to verify that the selected engine is running correctly and inspect its translations.

#### The Configuration Editor Tab

<img width="675" height="450" alt="MTUOC-server Manager Configuration Editor tab" src="https://github.com/user-attachments/assets/b97177f7-9ab5-4d16-972b-6994e2889df1" />

When you click **LOAD SELECTED CONFIGURATION & LINKED MODEL CONFIG**, the configuration files are loaded into two tabs: **1. Server Configuration (Main)** and **2. Model Configuration (Linked)**.

You can inspect and modify the configuration files and save your changes using the corresponding **SAVE** button at the bottom of the interface.

Note that changes are not applied to a running server. You must stop and restart the server for the new configuration to take effect.

#### The Aux. Editor Tab

The **Aux. Editor** tab allows you to edit additional text-based configuration files required by some models. You can open a file using the **OPEN** button, modify it, and save the resulting file using **SAVE AS**.

#### The Recipes Tab

The **Recipes** tab allows you to download complete engines, including models, alignment models, truecasers, and other required components, from a Hugging Face repository containing MTUOC recipes.

By default, the `aoliverg/MTUOC-recipes` repository is selected. If you change the repository, use the **CONNECT/REFRESH** button to update the list of available recipes.

You can filter the available recipes by entering a search string. Once you have identified the recipe you want to use, select it and click **DOWNLOAD SELECTED RECIPE**.

## Key Takeaways

After completing this section, you should remember that:

* **MTUOC** is an open-source ecosystem designed to facilitate the training, deployment, use, and integration of machine translation systems and LLMs in professional translation workflows.
* **MTUOC-server** acts as a bridge between translation engines and client applications, including CAT tools.
* The server manages the translation workflow by handling **preprocessing, inference, postprocessing, and communication with client applications**.
* MTUOC-server supports different **NMT systems, LLMs, and communication protocols**, allowing different translation technologies to be integrated through a common architecture.
* Features such as **tag restoration and translation memory integration** help adapt MT output to professional translation workflows.
* MTUOC-server can run on standard computers and can be operated either from the **command line** or through the **MTUOC-server-manager graphical interface**.
* **MTUOC recipes** provide a convenient way to download and configure complete, ready-to-use translation engines.
